# 本地数据与记录口径

当前数据库模式和 JSON 备份格式均为 `2`，支持导入格式一的旧备份。业务数据保存在名称包含站点路径的 IndexedDB 中，默认不发往远程服务。

## 记录规则

- 动作种子共 84 项，说明和分类由本项目独立编写。视频与衍生海报独立登记来源和 CC BY-SA 4.0 授权，详见动作示范文档。内置标识稳定为 `builtin-001` 至 `builtin-084`，前 37 项标识保持与首版一致，个人动作独立保存。种子版本二按稳定标识更新目录，保留收藏与归档状态，不更新历史训练或模板快照。
- 重量以整数克保存、千克输入，哑铃重量输入本组全部哑铃合计外部负重；徒手和辅助动作不推算负重训练量。
- 训练会话、模板、餐食保存其子项快照。修改动作或食物库不追溯更改历史。
- 食物营养按每百克填写，未知营养为 `null`，已知零为 `0`。份、杯、碗等换算必须先指定该食物每份克重。
- 克重允许一位小数；热量和营养素按未显示舍入的值计算，再在界面舍入。
- 全日饮食需主动确认完整；无食物时确认代表零摄入。增删或移动食物会取消受影响日期的完整确认。
- 目标从生效日期起使用，下一版本生效之前持续有效。体重每日只保留一条当前值。
- 每条记录持有固定归属日期；切换时区不移动历史日期，跨日训练默认留在开始日。

## 备份格式

顶层包含 `formatVersion`、`databaseVersion`、`appVersion`、`exportedAt`、`entities`。实体集合包含档案、动作、食物、训练、餐食、日记、目标、体重、训练模板及组合餐 `mealCombos`；内置字典、收藏、草稿和历史快照均在其中。

导入只支持完整替换。文件首先经过格式、版本、数值、重复标识、唯一日期、字典引用和训练/休息互斥验证；确认前无写入，事务失败保留原库。文件最大二十 MiB，当前拒绝未知格式版本。

每次普通更新使用实体 revision 检查，旧版本提交被拒绝；完整恢复或清空时更新数据库代际标识，旧页面事务不能写回新库。页面观察到代际变化后重新载入当前路由内容，关闭旧编辑界面。

后续若调整字段或拆分子表，须增加数据库迁移及备份格式转换测试；不能仅修改版本常量后忽略已有数据。

## 视频素材

视频和海报为站点静态资源，按稳定内置动作标识查找，不改变业务对象或历史快照。媒体缓存与个人记录分开，业务备份不包含视频文件；媒体无需独立业务表；当前数据库与备份格式见本文开头。

## 热量计算与 AI 草稿

本地计算输入和未确认的 AI 草稿仅存在页面内存，不写入档案。每日目标由用户确认后使用既有目标版本表保存。AI 草稿确认时原子写入新食物与餐食，备注保留估算来源和假设，未知营养项仍为 null。代理地址为构建配置，不是用户备份内容；AI 沿用既有食物与餐食结构，不单独增加数据库实体。

## 健身食谱

内置食谱为静态目录，浏览和调整份数不写数据库。确认计入饮食后，在单个事务中创建缺少的食谱估算食材并保存既有 Meal 格式，撤销目标日期的饮食完整确认；失败全部回滚。食材标识以 `recipe-ingredient-` 开头，重复入账复用引用，不覆盖用户编辑或归档。每次食谱入账使用当次目录估算快照；用户食物库中的后续编辑不会覆盖该估算，也不会改变历史。餐食备注保留菜名、份数、可食生重/干重口径、改编说明和固定提交来源。备份已包含食材与餐食，不需要调整数据库或备份格式。

## 健康组合餐与格式二

`mealCombos` 存储元信息、名称和一份组合的 `{ foodId, grams }` 明细，不复制食物营养。载入和计入时必须找到未归档的已登记食物，使用当前标签值；提交事务检查食物修订与数据库代际，避免预览后标签被其他页面更改。保存组合不入账，确认计入才生成独立餐食快照，并取消目标日期的饮食完整确认。

数据库由版本一增量增加 `mealCombos` 表，原表和记录不变；新备份使用 `formatVersion: 2, databaseVersion: 2` 并必含组合数组，校验组合引用和重复标识。版本一备份通过原格式严格验证后转换为空组合数组再恢复；新备份不能由旧版应用恢复。清空数据同时清空组合，恢复与写入失败均使用原有全库事务回滚。
