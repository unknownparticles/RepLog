# Proposal

## Why

训练、饮食和长期分析常分散在不同工具里，用户难以回答“这段时间吃得如何、练得是否持续”。RepLog 用同一日期组织餐食与训练，让记录和复盘形成完整流程，并支持离线使用。

## What Changes

- 提供月历、周视图与每日详情；每天显示训练状态、主要部位、已记录热量及饮食完整度。
- 建立可搜索的中文动作库，支持主要/辅助肌群、器械、动作类型、收藏与自建动作。
- 支持力量与有氧训练记录、逐组完成、历史参考、草稿恢复、训练模板及明确休息日。
- 支持早餐/午餐/晚餐/加餐、食物克重与份量、热量和蛋白质/碳水/脂肪、常用食物及整餐复制。
- 首版完整支持日、周、月、季度、年度分析，提供摄入趋势、目标对照、训练量、部位分布、频率、体重趋势和年度热力图。
- 提供可安装 PWA、离线读写、本地数据备份/恢复、基础体重记录和带生效日期的营养目标。

### Delivery Scope

首版覆盖以上全部能力；采用中文、单人本地档案、周一作为每周起点、首次初始化使用设备 IANA 时区。历史日期在时区变化后保持稳定。

云端账号与多设备同步、社交与教练系统、拍照估算热量、自动训练消耗/热量缺口、穿戴设备、条码与外部食物 API 放入后续独立变更。阶段拆分仅用于实施顺序，首版最终验收包含全部五个分析周期。

## Capabilities

### New Capabilities

- `calendar-journal`：月历/周视图、日期导航、日详情、饮食完整度与训练状态聚合。
- `exercise-library`：动作元数据、肌群与器械筛选、收藏、自建和历史引用保护。
- `workout-logging`：训练会话、逐组记录、力量/有氧指标、草稿、历史和模板。
- `nutrition-logging`：食物库、餐食、营养计算、历史快照、目标与完整度。
- `period-analytics`：五种周期、统一统计口径、图表、目标达成与体重趋势。
- `pwa-data`：安装与离线能力、本地档案、体重、备份恢复、升级和数据管理。

### Modified Capabilities

无，当前为空仓库。

## Impact

新增前端应用、浏览器本地数据库和 Service Worker 的设计约束；当前仅提交规格与实施任务，不交付运行中的应用。建议 React + TypeScript + Vite、IndexedDB/Dexie 和 ECharts，具体决策见 design.md。

涉及个人饮食、训练和体重数据；默认全部保存在当前浏览器，同源外链不携带日志数据。数据迁移与备份必须先验证再写入。参考项目与许可证核查见 [开源参考](../../../docs/references.md)。
